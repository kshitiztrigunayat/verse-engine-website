Verse Engine website developer handoff#

Prepared 30 October 2026. This package contains the responsive marketing website, its editable page generators and captured content, visual references, and instructions for maintenance and release. The website/dist/ directory is the deployable website. It is a static marketing and documentation frontend; the live Verse service continues to handle accounts, scene publishing and payments.

Reference website: https://verse-engine-ctruh-design.rajat83.chatgpt.site/

Start here#

  1. Extract the full archive. Open a terminal in website/.
  2. Use Node.js 22 or later. This handoff was checked with Node.js 24.19.0.
  3. Run node preview-server.mjs and open http://127.0.0.1:4173/.
  4. Run node tools/verify.mjs to check local resources, JavaScript syntax and JSON.
  5. To regenerate pages after content edits, run node source/build-production-pages.mjs from website/, then run verification again.

No dependency installation, API key, framework build or database is required. Serve the site over HTTP; opening HTML with file:// will prevent modules and fetched JSON from working correctly. Optional npm start, npm run build and npm run check shortcuts are included; there are no npm dependencies.

Delivered scope#

The website has 112 index routes, including Home, Developers, Pricing, Plug-ins, three core plug-in installation guides, About, Samples, 88 production documentation articles, an introductory overview and retained article aliases. All routes are listed in reference/routes.json. This count includes aliases and entry routes; it does not mean 112 unique articles.

The landing page keeps the approved sequence: particle-world story; possibilities; Take the Challenge; the three-step publishing workflow; plug-in workbench; FAQ; footer. The opening story progressively reveals an object, table, interior, building and neighbourhood. Its experience chapter changes between browser, phone and headset outlines.

Read before changing the site#

  • Retain approved product copy and the existing page sequence. Pricing, plug-in releases, documentation and sample destinations use the production snapshots supplied by the owner; product values are snapshots rather than a live sync.
  • Keep Degular headings and Metropolis body text. Use blue actions and highlights, light section surfaces, and white text on blue chapters. Keep the hero text dark on white.
  • The particle story is a custom illustrative Three.js scene. It is not the Verse rendering engine, a user-uploaded scene, or a measurement of the product's billion-triangle claims.
  • Account, checkout, callback, challenge and actual viewer journeys leave this frontend for the production service. Do not replace these with simulated success states.
  • About's unfinished company-story and team-photo blocks stay hidden, as requested by the owner.
  • Keep all assets, fonts and vendor/ files at their current paths. URLs are rooted at /; hosting below a subdirectory requires coordinated path changes.

Architecture and maintenance#

Stack and routing#

This is a buildless static multipage site with native browser JavaScript modules. Node.js is needed only for local preview, page generation and checks. Three.js revision 180 renders the landing illustration. GSAP 3.13.0 and ScrollTrigger control its scroll story, with Lenis 1.3.11 providing desktop smooth scrolling. Libraries are vendored under dist/vendor/; there is no CDN dependency for the main animation.

Each route has a physical index.html. For example, /pricing/ is dist/pricing/index.html, and /docs/guides/publish-from-blender/ is its nested index file. Use a static host that serves directory indexes and preserves real 404 responses. Canonicals and sitemap currently reference the design-site origin.

Generation model#

Run the production generator from website/. It imports the base generator first, then overwrites prototype pages with finished production content. Running only the base generator can restore outdated prices or incomplete prototype articles. Its intermediate log can mention unfinished articles; the production pass replaces those routes.

The generator reads the existing dist/index.html to retain the landing story, SVG artwork and current branding. It also relies on CSS, JavaScript and visual assets already in dist/. Do not delete dist/ before building, and do not configure a host to clean it as though it were disposable framework output. A framework migration must first separate these retained assets and the landing template from generated output.

The copied production generator includes the final publication corrections: four documentation sample links retain their published attributes, and the two sample cards that open guides retain explicit guide labels. This addition affects the handoff copy only. A rebuild was compared against the supplied runtime to check parity.

Editing recipes#

Change a landing headline: edit the chapter in dist/index.html. Preserve chapter IDs, data-chapter, data-jump, tab IDs and canvas/device hooks unless updating their JavaScript too. The page generator retains this section.

Change a shared header or footer: edit the helpers in source/build-site-pages.mjs, rebuild and inspect both landing and content pages. Landing has its own richer footer in dist/index.html; shared footer edits do not replace it automatically. Existing SVG branding is extracted from landing markup by the base generator.

Change a documentation article: edit its Markdown body, rebuild and inspect headings, TOC, tables and links. Adding an article also requires a navigation entry in production-docs.json with its data.page key. A Markdown file not in that navigation is not automatically published.

Change pricing: update the production plans snapshot and comparison source together. Rebuild to regenerate cards and pricing-data.json. Confirm plan allowances, annual multiplier, extra seats, offers, usage rates and checkout URLs all agree; changing just one displayed price is insufficient.

Release a plug-in: update version, filename, requirement, checksum, instructions and production download target together. Rebuild. Verify download availability and compare the displayed SHA-256 to the released package. The diagram and source timing labels are presentation content, not live upload telemetry.

Change samples: update the sample snapshot and local image assets. Two destinations have explicit overrides in sampleHref() because their supplied production cards currently opened guides. Update both override and label when actual viewer destinations become available.

Change the particle world: change geometry in world-data.js and camera/reveal fitting in model.js; adjust the scroll mapping in app.js only when necessary. Recheck the table supports, interior visibility, and building centering in every device outline at desktop and phone widths. Some historical pose fields remain in app.js; the current renderer only consumes a subset, so changing an unused field will not affect the picture.

Useful debugging paths#

  • /?motion-off uses the static readable story for reduced-motion review.
  • /?poster is a retained poster capture mode, not the normal visitor experience.
  • The canvas host exposes data-vertex-count; this is the illustration's point count, not the product triangle benchmark.
  • data-progress and data-scroll-progress on the story expose its resolved chapter and scroll timeline values.

Design system and interactions#

Visual rules#

The current system combines Ctruh typography with the owner's Apple design reference for colors, controls and spacing. Preserve the fonts and page flow. Use rectangular photographic cards, realistic environment imagery, blue primary actions and white or pale surfaces. The hero uses dark text on white. Blue story chapters use white type. Avoid black section backgrounds and decorative gradients or generic illustrations.

Degular Medium/Semibold supplies headings and wordmarks; Metropolis Regular/Semibold supplies body text and controls. Font files are local. Shared-page body text is 16px at 1.6 line height. Large headings use fluid clamp() values; copy these rules from site.css rather than freezing a desktop screenshot size. Shared header height is 84px, with a 106px document scroll-padding offset.

Primary actions have a blue fill, white text, pill radius, approximately 11px × 22px padding and at least 44px targets. Secondary controls use readable blue/ink outlines or lighter surfaces. Press feedback may scale to .95. Body sections generally use an 80px desktop / 48px phone rhythm; individual templates adjust this for editorial layouts.

Landing story contract#

The story uses a single procedural point-cloud scene and one camera. Geometry levels gradually reveal the vessel, table/furniture, interior, building and neighbourhood in shared world coordinates. Surface points are illustrative vertices; the scene is not a production Verse model or a photogrammetry capture.

app.js drives raw timeline values 0–7. Values 0–4 move through the first chapters. Values 4–6 hold the experience chapter while the device changes Web 3D → AR → XR. Values 6–7 resolve to the final chapter. Chapter seeking and experience tabs share that timeline; they should not start separate competing animation clocks.

ScrollTrigger pins the stage for roughly eight viewport heights on desktop and 7.4 on phone, with a .7 scrub. Lenis is initialized above 800px. The 3D renderer samples less geometry below 600px and caps pixel ratio at 1.3 on mobile / 1.6 elsewhere. These are implementation values, not measured frame-rate guarantees.

The device outline is sampled at 128 points per source SVG path and interpolated by device-morph.js. Browser, phone and headset chrome fade according to the same phase. model.js projects the primary building bounds into the usable device region and compensates for SVG letterboxing. If changing SVG shapes, update their corresponding fit regions too.

The pause control stops ambient camera motion; it does not disable user-driven scroll progress. Reduced motion uses a static, sequentially readable layout. WebGL import/initialization failure selects the static story; fallback.js also reveals static content after a five-second enhancement timeout. Keep the poster SVG available. When changing the story, test both enhancement success and the static fallback.

Responsive and accessibility expectations#

Previously reviewed widths were 320px, 390px, 768px and 1440px. Use these as regression points and also resize between them. This CSS has component-specific breakpoints rather than one universal mobile cutover. The landing timeline and renderer also make width decisions in JavaScript; reload after crossing breakpoints when testing initial setup. Live cross-breakpoint behavior warrants explicit regression review.

At narrow widths, titles must fit, device content must remain centered, tables/code must scroll within their region, and gallery cards must remain rectangular. Do not hide overflow globally to disguise a layout defect.

Preserve native links/buttons, skip links, visible focus, real labels, tab ARIA relationships, inactive story-panel inert state, reduced-motion handling, image alt text and 44px action targets. Validate keyboard-only operation and contrast after edits. Prior manual checks are not an accessibility certification.

Pricing behavior#

The captured USD monthly base prices are Free $0, Starter $29, Pro $99 and Scale $499. Included seats are 1, 1, 3 and 10 respectively. Paid-plan extra seats are $15 per seat/month; annual estimates use ten monthly units. These are the handed-off snapshot, not a promise that production prices never change.

The displayed estimate is (base + extra seats × seat price) × billing factor, where the annual factor is 10. Example: annual Pro with five seats is (99 + 2 × 15) × 10 = $1,290/year. Taxes and final seats are confirmed on the live service. Pay-as-you-go stays labelled Coming soon. Enterprise, trial discounts, broker packs and allowances must be refreshed from product content together.

The callback form is intentionally on the production site; a public cross-origin callback endpoint was not established for this frontend. There is no local form pretending a request has been sent. Unused generic mailto and feedback handlers remain in site.js, but current production templates do not expose them as a backend.

Hosting and domain changes#

Upload website/dist/ as the static web root. Preserve nested directory indexes, JS module MIME types, JSON, font types, SVG and image delivery. Use HTTPS for clipboard and browser capabilities. Serve missing routes as 404 with 404.html; do not rewrite every request to the home page. A host that redirects /pricing to /pricing/ is compatible.

For a new domain, replace the design-site origin in the base generator and the production generator's sitemap writer. Rebuild, then update the retained landing canonical, Open Graph image URL and robots.txt sitemap address. Scan all canonical/Open Graph/sitemap output for the old origin. Preserve real product-service URLs unless changing product infrastructure too.

The existing design Site's audience is owner-controlled. Publishing this archive on another host is a separate release decision; no credentials or account access are bundled here. The local preview server is not intended for public hosting.

Release checks#

  1. Back up the current runtime and content snapshots. Make changes in source templates or the owned runtime modules, not generated article HTML alone.
  2. Rebuild from website/ and run node tools/verify.mjs.
  3. Start the local server; run node tools/verify.mjs --http=http://127.0.0.1:4173.
  4. Review Home, Developers, Pricing, Plug-ins, all three install guides, About, Samples, a long API article and an article with a wide table at 320/390/768/1440px.
  5. Check all particle stages, visible table legs, device centering, Web/AR/XR transitions, gallery keyboard controls, inspector pan/zoom, navigation, FAQ, and reduced-motion/WebGL fallback.
  6. Verify monthly/annual calculations, extra seats and final checkout targets without completing a payment. Check code copying, article search, About tabs and downloads/checksums.
  7. Refresh time-sensitive product prices, releases, offers, URLs and claims from the production owner. Confirm About placeholders remain hidden.
  8. Confirm production domain metadata, asset credits, font rights and actual link destinations. Perform accessibility and performance review on target devices.
  9. Deploy the complete dist/ tree. Check direct deep links, a missing route, fonts, modules and local JSON on the deployed host. Keep the previous release available for rollback.

Prior visual QA covered the listed widths and interactive journeys; it did not establish a Lighthouse score, hardware/browser coverage matrix, formal accessibility audit or a frame-rate guarantee. The handoff QA report records which checks were rerun for this package.
